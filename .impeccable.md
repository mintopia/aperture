## Design Context

### Users
Two primary user groups across all event sizes (small meetups to 100+ tournaments):
- **LAN Attendees**: Gamers of varying technical ability connecting devices at LAN parties. They interact with the captive portal on a blocked device, authenticate via phone, then use a dashboard. Primary needs: speed, efficiency, confidence that things work.
- **Network Admins**: Technical staff managing network infrastructure during live events. Need fast lookup, quick actions, and professional tooling. Under time pressure during events.

### Brand Personality
- **User-Facing**: Gaming & Energetic meets Friendly Technical — approachable, fun, but sharp and efficient. Inspired by Discord, Steam.
- **Admin-Facing**: Modern Professional meets Friendly Technical — clean, data-rich, zero fluff. Inspired by Linear, Vercel, modern SaaS tools (no monetisation focus).

### Aesthetic Direction
- **Theme**: Dark mode + light mode (both supported, user-toggleable)
- **Theming System**: CSS custom properties with admin-customisable colours. 4 bundled themes: Cool Neon (blue/cyan), Warm Neon (pink/magenta), Matrix (green), Amber Glow (orange). Each has light and dark variants.
- **Typography**: Inter font family (already in use), bold hierarchy
- **Anti-references**: Generic dashboards, monetisation-focused SaaS, cluttered enterprise tools
- **Key constraint**: All assets served locally (no CDN) — LAN party captive portal context

### Design Principles
1. **Speed over spectacle** — Every interaction should feel instant. Optimistic UI, fast polling, minimal friction.
2. **Two audiences, two experiences** — User portal feels like a gaming platform; admin panel feels like a professional tool. Same design system, different expressions.
3. **Themeable by default** — Every colour decision goes through CSS custom properties. Admins own their event's brand.
4. **Offline-first portal** — The captive portal works with zero external dependencies. Vanilla JS, local assets only.
5. **Clarity under pressure** — Admins use this during live events with 100+ users. Information must be scannable, actions must be obvious.

### Accessibility
- WCAG AA compliance
- Reduced motion support
- Colour blindness considered in all theme designs
- Keyboard navigation throughout
