## Design Context

### Users
Two primary user groups across all event sizes (small meetups to 100+ tournaments):
- **LAN Attendees**: Gamers of varying technical ability connecting devices at LAN parties. They interact with the captive portal on a blocked device, authenticate via phone, then use a dashboard. Primary needs: speed, efficiency, confidence that things work.
- **Network Admins**: Technical staff managing network infrastructure during live events. Need fast lookup, quick actions, and professional tooling. Under time pressure during events.

### Brand Personality
- **User-Facing**: Gaming & Energetic meets Friendly Technical — approachable, fun, but sharp and efficient. Inspired by Discord, Steam.
- **Admin-Facing**: Modern Professional meets Friendly Technical — clean, data-rich, zero fluff. Inspired by Linear, Vercel, modern SaaS tools (no monetisation focus).

### Aesthetic Direction
- **Theme**: Dark mode + light mode (both supported, admin-configurable default, user-toggleable)
- **Theming System**: CSS custom properties with admin-customisable colours. 5 bundled themes: Aperture Default (indigo/rose on warm zinc), Neon Circuit (cyan/magenta on cool slate), Forest LAN (emerald/amber on olive-tinted dark), Sunset Arena (orange/pink on warm brown-tinted dark), Midnight Ice (blue/teal on deep blue-tinted dark). Each has light and dark variants.
- **Typography**: Space Grotesk (headings, 600-700 weight), Plus Jakarta Sans (body, 400-700 weight), JetBrains Mono (code/data, 400 weight). NOT Inter — it was replaced as it is the #1 AI-generated font tell.
- **Colour palette** (default theme): Warm zinc neutrals (NOT slate — user explicitly hates slate). Dark bg: #1a1a1e, surface: #252528. Light bg: #faf9f7, surface: #ffffff. Primary: indigo #818cf8 (dark) / #6366f1 (light). Accent: rose #fb7185 (dark) / #e11d48 (light). Muted text: #9a9990 (dark) / #6b6a60 (light) — passes WCAG AA at ~5:1 contrast.
- **Anti-references**: Generic dashboards, monetisation-focused SaaS, cluttered enterprise tools, AI-generated aesthetics (no gradient text, no glassmorphism, no cyan-on-dark neon, no uniform card grids)
- **Key constraint**: All assets served locally (no CDN) — LAN party captive portal context. Fonts must be self-hosted for captive portal pages (user device has no internet).

### Design Principles
1. **Speed over spectacle** — Every interaction should feel instant. Optimistic UI, fast polling, minimal friction.
2. **Two audiences, two experiences** — User portal feels like a gaming platform; admin panel feels like a professional tool. Same design system, different expressions.
3. **Themeable by default** — Every colour decision goes through CSS custom properties. Admins own their event's brand.
4. **Offline-first portal** — The captive portal works with zero external dependencies. Vanilla JS, local assets only.
5. **Clarity under pressure** — Admins use this during live events with 100+ users. Information must be scannable, actions must be obvious.

### Layout Patterns
- **Admin sidebar**: 172px fixed width, collapses to horizontal inline nav at ≤1024px. Contains: brand, Overview section (Dashboard), Management section (Users, IPs, Ports), Tools section (Content, Settings). Active item uses primary-bg + primary colour.
- **Detail pages** (User/IP/Port): Horizontal metadata strip (flex row, baseline-aligned, 28px gap) at top below breadcrumb. Content below — no left/right info panel split. Strip wraps on smaller screens.
- **Portal dashboard**: Varied grid layout with banner, alert, 2fr:1fr bandwidth+connection, quick links row, event info. NOT uniform cards.
- **Admin dashboard**: Hero stat card (green-tinted), DHCP pools with progress bars, port errors list, user table with pagination.
- **Settings**: Separate sidebar nav (172px) for settings categories with Integrations/Appearance/General sections.

### Component Patterns
- **Charts**: Dual-colour bandwidth with primary (solid line) = download/inbound, accent (dashed line) = upload/outbound. Area fill under primary line using SVG linearGradient. Chart-fill opacity: 0.15 dark, 0.3 light. Always includes legend.
- **Status pills**: Include ::before pseudo-element icons for accessibility — ✓ (ok/green), ✕ (bad/red), ▲ (warn/yellow). Never rely on colour alone.
- **Tables**: Rows with `.clickable` class get cursor:pointer + 2px left-border accent on hover. Monospace data at minimum 11px.
- **Pagination**: "Showing 1–25 of N items" left-aligned + numbered page buttons right-aligned. Below table with top border separator.
- **Forms**: Labels at 12px semibold, inputs at 13px with 8px 12px padding. Required fields: red asterisk. Optional fields: "(optional)" text in muted colour. Focus state: primary border + glow ring.
- **Empty states**: Dashed border card, centered SVG icon (32px), title (13px semibold), description (11px muted), optional CTA button.
- **Toggle switches**: 32×18px, green=on, surface-h=off, white knob with subtle shadow.
- **Code blocks**: JetBrains Mono 10px, dedicated --code-bg/#151517 dark, #e8e7e3 light — distinct from card surface.
- **Preview chrome**: Dashed borders, --preview-bg distinct from --bg, "PREVIEW" tag in accent colour.
- **Alerts**: Left icon (24px rounded square) + content. Warn=yellow bg+border, DNS example.
- **Banners**: Full-width, left 3px border accent, content + right badge. Event banner with "● Live" accent badge.

### Responsive Strategy
- **≤1024px** (tablet): Admin sidebar → horizontal nav bar (icon + label per item, section headers hidden). All grids → single column. Detail strips wrap. Settings nav horizontal. Builder palette horizontal row.
- **≤640px** (mobile): Captive portal must work — smaller QR (140px), heading 18px, device code large but clamped. Portal header stacks vertically. Search bar hidden. All grids single column. Config blocks 9px. Builder canvas 6-column.
- **Captive portal pages (S1/S2/S3) are mobile-critical** — users scan QR on phones.
- **Admin pages (S4-S9) are desktop-first** — tablet support important, mobile is nice-to-have.

### Accessibility
- WCAG AA compliance — all text-3 muted text passes 4.5:1 minimum contrast
- Reduced motion support (respect prefers-reduced-motion)
- Colour blindness: status pills use ✓/✕/▲ icons, not colour alone
- Keyboard navigation throughout (tabindex, role, focus-visible states on all interactive elements)
- Form inputs: required/optional clearly indicated
- Screen reader: ARIA labels on icon-only buttons, navigation landmarks
