## Design Context

### Users
Two primary user groups across all event sizes (small meetups to 100+ tournaments):
- **LAN Attendees**: Gamers of varying technical ability connecting devices at LAN parties. They interact with the captive portal on a blocked device, authenticate via phone, then use a dashboard. Primary needs: speed, efficiency, confidence that things work.
- **Network Admins**: Technical staff managing network infrastructure during live events. Need fast lookup, quick actions, and professional tooling. Under time pressure during events.

### Brand Personality
- **User-Facing**: Gaming & Energetic meets Friendly Technical — approachable, fun, but sharp and efficient. Inspired by Discord, Steam.
- **Admin-Facing**: Modern Professional Technical — clean, data-rich, zero fluff. Evokes **confident control**. Inspired by Linear, Vercel, modern SaaS tools (no monetisation focus).

### Aesthetic Direction
- **Theme**: Dark mode + light mode (both supported, admin-configurable default, user-toggleable)
- **Theming System**: Single "Dispatch" theme using OKLCH color space with warm charcoal base (hue 60). Admin-configurable accent hue (0–360 integer). 8 presets:
  - Pink/350, Coral/20, Tangerine/55 (default), Lime/135, Teal/185, Sky/230, Violet/295, Magenta/325
- **Default theme**: `dispatch` dark (set in `useTheme.js`)
- **Theme CSS files**: `resources/css/themes/dispatch.css` (single file)
- **Theme composable**: `resources/js/composables/useTheme.js` — manages mode (dark/light) in localStorage, integrates accent hue application. Single theme, no theme switching.
- **Accent hue composable**: `resources/js/composables/useAccentHue.js` — derives 7 CSS variables from a single hue integer at runtime
- **Typography**: Bricolage Grotesque (variable, headings, 200-800 weight), Hanken Grotesk (variable, body, 100-900 weight), JetBrains Mono (code/data, 400 weight). All locally hosted. NOT Inter, Space Grotesk, or Plus Jakarta Sans — all were replaced.
- **Colour palette**: OKLCH warm charcoal (hue 60). Dark bg: oklch(13% 0.006 60), surface: oklch(17% 0.006 60). Light bg: oklch(97% 0.004 60), surface: oklch(100% 0 0). Primary/accent: derived from admin-configurable accent hue (default tangerine, hue 55). Semantic: success oklch(72% 0.17 155), warning oklch(78% 0.15 85), danger oklch(65% 0.2 25), info oklch(70% 0.1 240).
- **CSS Variables**: `--color-primary`, `--color-accent`, `--color-accent-dim`, `--color-accent-text`, `--color-success`, `--color-warning`, `--color-danger`, `--color-info`, `--color-glow`, `--color-bg`, `--color-surface`, `--color-surface-hover`, `--color-text`, `--color-text-secondary`, `--color-text-muted`, `--color-border`, `--color-border-hover`, `--color-input-bg`
- **Anti-references**: Generic dashboards, monetisation-focused SaaS, cluttered enterprise tools, AI-generated aesthetics (no gradient text, no glassmorphism, no cyan-on-dark neon, no uniform card grids), bland and subtle designs
- **Key constraint**: All assets served locally (no CDN) — LAN party captive portal context. Fonts must be self-hosted for captive portal pages (user device has no internet).

### Design Principles
1. **Speed over spectacle** — Every interaction should feel instant. Optimistic UI, fast polling, minimal friction.
2. **Two audiences, two experiences** — User portal feels like a gaming platform; admin panel feels like a professional tool. Same design system, different expressions.
3. **Themeable by default** — Every colour decision goes through CSS custom properties. Admins own their event's brand.
4. **Offline-first portal** — The captive portal works with zero external dependencies. Vanilla JS, local assets only.
5. **Clarity under pressure** — Admins use this during live events with 100+ users. Information must be scannable, actions must be obvious.
6. **Bold, not bland** — The UI should have personality and visual confidence. Avoid generic/muted aesthetics.

### Tech Stack
- **Backend**: Laravel 12 (PHP 8.5), Inertia.js
- **Frontend**: Vue 3 (Composition API), Tailwind CSS 4, Chart.js
- **Build**: Vite 8, laravel-vite-plugin
- **Testing**: PHPUnit (PHP), Vitest (JS), Playwright (E2E)
- **Linting**: Laravel Pint (PHP), ESLint + Prettier (JS)

### Layout Patterns
- **Admin sidebar**: 220px fixed width, collapses to horizontal inline nav at ≤1024px. Contains: brand, Overview section (Dashboard), Management section (Users, IPs, Switches, DHCP), Statistics section (Stats), Tools section (Content, Settings). Active item uses bg-[var(--color-accent-dim)] + text-[var(--color-primary)] + font-semibold — background fill, no left border.
- **Detail pages** (User/IP/Port): Horizontal metadata strip (flex row, baseline-aligned, 28px gap) at top below breadcrumb. Content below — no left/right info panel split. Strip wraps on smaller screens.
- **Portal dashboard**: Varied grid layout with banner, alert, 2fr:1fr bandwidth+connection, quick links row, event info. NOT uniform cards.
- **Admin dashboard**: Hero stat card (green-tinted), DHCP pools with progress bars, port errors list, user table with pagination.
- **Settings**: Separate sidebar nav (172px) for settings categories with Integrations/Appearance/General sections.

### Component Library
UI components in `resources/js/Components/UI/`:
- **AlertBanner** — Contextual alerts with background tint and full border. No left accent stripe.
- **CapabilityTag** — Feature capability badges
- **ConfigBlock** — Syntax-highlighted code display (JetBrains Mono)
- **ConfirmModal** — Confirmation dialogs with danger/warning variants
- **ConnectedDevicesSummary** — Device cards with user/IP/MAC links
- **DataTable** — Full-width tables with hairline row dividers. Clickable rows use bg hover, no border-l-2 accent.
- **EmptyState** — Simple text placeholder — no dashed border card.
- **FlashMessages** — Toast-style flash notifications
- **FormField** — Label + input wrapper with validation
- **MetadataStrip** — Horizontal metadata bar with named slot system
- **Pagination** — "Showing X–Y of Z" + page buttons
- **ProgressBar** — DHCP pool utilisation bars
- **SectionHeader** — Section titles with optional action slot — uses size contrast only (uppercase, tracking-wider, muted color). No accent lines.
- **StatCard** — Open layout stat display — label + value, no card container. Optional color and label dot.
- **StatusPill** — 5 variants (success/danger/warning/info/neutral), icon+label
- **TimeSeriesChart** — Chart.js wrapper for bandwidth/error charts

### Component Patterns
- **Charts**: Dual-colour bandwidth with primary (solid line) = download/inbound, accent (dashed line) = upload/outbound. Area fill under primary line using SVG linearGradient. Chart-fill opacity: 0.15 dark, 0.3 light. Always includes legend.
- **Status pills**: Include ::before pseudo-element icons for accessibility — ✓ (ok/green), ✕ (bad/red), ▲ (warn/yellow). Never rely on colour alone.
- **Tables**: Clickable rows get cursor:pointer + bg-[var(--color-surface-hover)] on hover. No border-l accent. Monospace data at minimum 11px.
- **Pagination**: "Showing 1–25 of N items" left-aligned + numbered page buttons right-aligned. Below table with top border separator.
- **Forms**: Labels at 12px semibold, inputs at 13px with 8px 12px padding. Required fields: red asterisk. Optional fields: "(optional)" text in muted colour. Focus state: primary border + glow ring.
- **Empty states**: Simple text layout — muted text description, optional CTA. No dashed border card.
- **Toggle switches**: 32×18px, green=on, surface-h=off, white knob with subtle shadow.
- **Code blocks**: JetBrains Mono 10px, dedicated --code-bg/#151517 dark, #e8e7e3 light — distinct from card surface.
- **Preview chrome**: Dashed borders, --preview-bg distinct from --bg, "PREVIEW" tag in accent colour.
- **Alerts/Banners**: Background tint (5% opacity) with full border (20% opacity). No left border accent stripe.

### Responsive Strategy
- **≤1024px** (tablet): Admin sidebar → horizontal nav bar (icon + label per item, section headers hidden). All grids → single column. Detail strips wrap. Settings nav horizontal. Builder palette horizontal row.
- **≤640px** (mobile): Captive portal must work — smaller QR (140px), heading 18px, device code large but clamped. Portal header stacks vertically. Search bar hidden. All grids single column. Config blocks 9px. Builder canvas 6-column.
- **Captive portal pages (S1/S2/S3) are mobile-critical** — users scan QR on phones.
- **Admin pages (S4-S9) are desktop-first** — tablet support important, mobile is nice-to-have.

### Accessibility
- WCAG AA compliance — all text-3 muted text passes 4.5:1 minimum contrast
- Reduced motion support (respect prefers-reduced-motion)
- Colour blindness: status pills use ✓/✕/▲ icons, not colour alone
- Keyboard navigation throughout (tabindex, role, focus-visible states on all interactive elements)
- Form inputs: required/optional clearly indicated
- Screen reader: ARIA labels on icon-only buttons, navigation landmarks
